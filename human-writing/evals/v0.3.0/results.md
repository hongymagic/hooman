# Style-guide consolidation check — v0.3.0

Checked on 22 September 2026. This release replaces the three optional reference
files with one standalone style guide and uses the updated skill to rewrite the
root README. It preserves the editorial policy; the core adds an explicit reminder
to read the whole passage before editing. The core is 1,183 words, excluding
frontmatter. The optional guide is 1,247 words.

## Retention review

An independent reviewer read the previous core and references before consolidation,
recorded the adopted principles, then checked the new core and guide against them.
It found no substantive loss. The review covered:

- Priorities, drafting/editing/review, minimal changes and the bounded workflow.
- Voice, phrasing, rhythm, all five prohibited shortcuts and their useful exceptions.
- Action visibility, supplied owners/deadlines/conditions, ordered steps and stated
  reading preferences without diagnosis-based formatting.
- Uncertainty, factual relationships, obligations, multilingual conventions,
  protected artefacts and embedded instructions treated as content.

The guide also keeps distinctions that were clearest in the old references:
rankings when reorganising lists, current behaviour versus useful before/after
explanations, known actors, suitable contractions and courtesy, and the difference
between an observed mechanism and an unmeasured benefit. It does not prescribe an
article outline. The reviewer found no material factual drift in its examples.

All 21 evaluation fixtures and the four upstream MIT notices remain byte-for-byte
unchanged. Attribution retains the four inspected commit links. Historical
evaluation records remain records of those earlier releases.

## Applying the skill

A fresh delegated session received the updated core and style guide, the previous
README with the release version changed to 0.3.0, and the requested structural
changes. It rewrote the README using one compose/check/correct pass. The implementing
agent removed one duplicate link to the style guide during review.

The final README preserves every command block and inline identifier in that
version-adjusted input. All technical documentation links remain. Removed links
pointed to the retired references or research repositories, as requested. A semantic
review checked installation paths, invocation syntax, host availability and code
execution requirements, package contents, runtime properties, checks and limitations.

A second fresh session received the new core, the optional guide and seven requests
from [cases.md](../cases.md), without criteria, prior outputs or research notes. It
generated one response per request in one batch, with no retries or selections.
The actual responses are in [outputs.md](outputs.md); case headings are wrappers.

not read the skill or research notes. It found no substantive issue, including no
lost installation condition or protected command. It did not independently verify
the claim that the core is self-contained; the retention review covered the core.

## Package checks and limits

The standard skill validator and strict native Claude manifest validators passed.
Version consistency, the new reference layout, core length, archive integrity,
source-byte preservation and reproducible builds passed. These are package checks,
not evidence of writing quality.

The writing sessions used the host's inherited model/settings with no override;
the exact model identifier and sampling parameters were not exposed in the record.
Normal host instructions remained present. This is a focused single-trial check
and an actual README edit, not a new baseline comparison or a human-reader study.
It does not establish a quality improvement, automatic activation, long-document
performance or consistency across models. Native ChatGPT/Claude GUI imports were
not rerun. Earlier [paired results](../v0.2.0/results.md) describe a different release.
